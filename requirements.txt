# PINNED DELIBERATELY. The session cookies in NOTEBOOKLM_AUTH_JSON are minted by
# `notebooklm login` on a local machine, so the local and CI versions must agree
# on which Google host they target. When Google rebranded NotebookLM to Gemini
# Notebook (notebooklm.google.com -> notebook.google.com), only 0.8.0+ followed;
# older clients still fetch the token from the dead host and report the session
# as "expired or invalid" no matter how recently you logged in.
# Upgrade this pin and re-run `notebooklm login` together, never separately.
#
# 0.8.6, not 0.8.0: Google now answers a signed-out request with a token-less
# landing page instead of redirecting to sign-in. 0.8.0 read that as "CSRF token
# not found in HTML ... page structure has changed", which looks like a library
# break rather than the expired session it was (Oct 2026, 19 failed runs).
# 0.8.5+ asks /login and reports it as "Authentication expired".
